# What's new in LUME Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** At a person's first page after an update, a near full-screen window plays the version's new features in LUME's own components; "Show me" takes them to each one with a spotlight; "New" pills, a Today pill, Settings → About and the profile menu bring it back.

**Architecture:** Releases are data in `@lume/core` (version, date, stories with route/target/permission/needs). The API keeps one `whats_new` jsonb per person and tells `/auth/me` which of the running version's stories this person may see and whether the window is due. The web mounts a `WhatsNewProvider` in the shell: the window (overture, rail, stage, coded demos), the Show me spotlight (the tour's `Spotlight` + `cardPosition`), the pills.

**Tech Stack:** Next.js client components, CSS modules on LUME tokens, `motion` (already used by AiGlyph), Fastify + Drizzle, Zod, Vitest, Playwright.

## Global Constraints

- Version shown, never a month name: "What's new in 1.2.0"; the roll goes from the previous release ("1.1.0") to this one.
- LUME's logo is `public/lume-mark.png` as it is (never redrawn or resized off its ratio); LUME AI is `AiGlyph` with `draw="loop"` (`"pen"` while a demo writes); WhatsApp is `public/brand/whatsapp.svg`.
- Window: 3vh/3vw from each edge, 8px on a phone (≤560px); the full-window scrim (sidebar and top bar dimmed and blurred too).
- Each story plays 7-9 s by itself; arrows, rail and Next move it; Esc closes. Reduced motion: no roll, no flight, each story shows its finished state, no autoplay.
- No text ever cut: any mask that hides overflow around text reaches past descenders (`padding-bottom: .12em` with matching negative margin, as the mock's `.headline .line`).
- Copy speaks as LUME, no em dashes, no "we", no he/she; never claims what isn't true for this business (stories whose feature is off here aren't shown).
- Both themes (Porcelain, Obsidian), widths 1024-1920 and 390.
- Sounds: none (the window isn't an achievement).

## Decisions made for this plan (recorded in the spec's Decisions on completion)

- **Release 1.2.0 stories** (the mock's, updated to what shipped since):
  1. `calls`, kicker LUME AI: "LUME AI books / your calls." "Give it the times you take calls. When a lead asks for one and you're free, it says yes, books it and sends the Google Meet link if you let it." Place `/settings/ai`, target `calls`, permission `settings.manage`, needs `ai`.
  2. `chats`, kicker WhatsApp: "Your chats, / live in LUME." "A lead's message shows the moment it arrives, with a notice on whatever screen you're on, and their chat opens in its own window." Place `/replies`, target `nav-replies` (the sidebar item), permission `leads.view`, needs `whatsapp`.
  3. `templates`, kicker LUME AI: "Templates, / written for you." "Say what a template is for and LUME AI writes a few to choose from. In a chat, one tap puts yours in the reply box." Place `/templates`, target `write-with-ai`, permission `templates.manage`, needs `ai`.
  Also new (one line each, no Show me): "The two-step code is ready to type, no click first"; "Lift do not contact from LUME AI's chat"; "Delete your own account, from My account"; "Profile photos save from every browser".
- **Who sees the window:** a person whose account was made on or after the release date doesn't (everything is new to them: onboarding and the tour cover it); their state is set to seen on their first `/auth/me`. Nobody sees it while onboarding, the agreement or two-step enrolment is due.
- **Never during a task:** the window waits while an `[aria-modal="true"]` dialog is open, the tour is running, or the path starts with `/setup`, `/onboarding`, `/settings/imports/` (an import in progress); it checks again on each route change.
- **Server-kept state** (`users.whats_new` jsonb): `{ seen: string | null, used: string[], pillGone: string | null }`. `used` holds `"<version>:<storyId>"`.
- **"New" pills:** beside the sidebar item of a story's route and beside its target, while `now < release.date + 7 days` and the story isn't used. Used = Show me pressed for it, or its route opened.
- **The profile menu "What's new"** opens the newest release's window; a version select in the window's header appears only when more than one release exists (one exists now).

## Review Focus

1. A person who can't open a story's place (a rep without `settings.manage`) never sees that story, its pill or its Show me; if no story is left, no window at all (Task 2 tests, Task 5 test).
2. A business with LUME AI or WhatsApp off isn't told about them (Task 2 test: `needs` filters).
3. The window opening over a sheet or an import mid-flight (Task 4 test: waits for the dialog to close).
4. Show me when the target isn't on the page (still loading, or the element isn't there for this person): the tip shows centred with no spotlight after 3 s, never a spotlight on nothing (Task 6 test).
5. A second tab or device: seen on one is seen everywhere; the window never opens twice in one session after "seen" is saved (Task 2 + Task 4 tests).

**Interfaces:**
- Produces:
  ```ts
  type StoryId = "calls" | "chats" | "templates";
  type Story = { id: StoryId; kicker: "lume-ai" | "whatsapp" | "lume"; head: [string, string]; sub: string;
    ms: number; place: { route: string; target: string }; permission: PermissionKey;
    needs: "ai" | "whatsapp" | null; tip: { title: string; body: string } };
  type Release = { version: string; from: string; date: string /* YYYY-MM-DD */; stories: Story[]; alsoNew: string[] };
  const RELEASES: Release[]; // newest first
  type WhatsNewState = { seen: string | null; used: string[]; pillGone: string | null };
  const EMPTY_WHATS_NEW: WhatsNewState;
  function releaseFor(version: string): Release | null;               // exact match
  function storiesFor(r: Release, o: { can: (p: PermissionKey) => boolean; on: { ai: boolean; whatsapp: boolean } }): Story[];
  function windowDue(o: { state: WhatsNewState; release: Release | null; stories: Story[]; joinedAt: Date }): boolean;
  function isNew(o: { state: WhatsNewState; release: Release; story: StoryId; now: Date }): boolean;
  ```
