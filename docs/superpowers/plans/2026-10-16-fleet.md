# Fleet Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every client's LUME reports its health with each check-in; the licence dashboard shows the fleet worst
first, a Health card per client and bell alerts; the owner publishes announcements that reach chosen LUMEs inside
the signed answer and show there as a "From LUME's team" strip.

**Architecture:** `@lume/core` owns the shapes (check body health, the announcement claim, the problem keys). The
licence server stores health per check-in (`check_ins.health`), works out status, and signs announcements only for
installs that list `accepts: ["announcements"]`. LUME's API reads its own health (readHealth + a 5xx counter + disk +
DB size), sends it, verifies and keeps announcements in the token, filters them per person, and stores Got it per
person. The web shows the strip and the About list.

**Tech Stack:** TypeScript, zod, Postgres (pg, drizzle in LUME), Next.js (licence panel and LUME web), Fastify (LUME
API), vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-10-16-fleet-design.md` · Canvas: https://claude.ai/artifact/32HRBdpQw1i356NZzGeHhu

## Global Constraints

- Nothing about a lead, a contact or a source's name leaves a client's server: counts, sizes, times, fixed keys.
- An install that doesn't send `accepts` gets a signed payload with exactly today's keys (no `announcements` key).
- Problem keys: `reminders_late`, `sweeper_stopped`, `jobs_unreadable`, `jobs_failed`, `digest_failing`, `source`,
  `restore_test` — no others.
- Limits: ≤ 3 announcements per answer; title 1–80; body 1–600; `ends_at` ≤ 60 days after `starts_at`.
- Status rules (§2.2): down > 24 h; needs a look = any problem key, disk < 15%, failed24h > 0, errors24h ≥ 20, restore
  test failed or > 8 days; no health yet = live but no `health`; else healthy. Disk < 5% is the red alert.
- Look: the panel's tokens and components; LUME's tokens; no violet; no AI slop; springs/transitions with
  reduced-motion fallbacks. Copy as LUME; announcement text is plain text everywhere.
- Lint forbids SQL built in template literals; no hand-written vendor prefixes in the web's CSS modules.

## Review Focus

1. **An older LUME checking in to the new licence server** → its signed answer is unchanged (no new key), so it
   doesn't turn read-only (Task 2: payload keys equal today's for a body without `accepts`).
2. **Health reading fails on a client's server** (pgboss missing, statfs refused) → the check-in still goes, without
   `health` or with nulls (Task 5).
3. **An announcement withdrawn or ended** → gone from the next answer, and LUME hides one whose `endsAt` has passed
   even from a cached token (Tasks 2, 5).
4. **Admins-only announcement** → never in a non-admin's licence view or About list (Task 5).
5. **Text with HTML or very long words** → shown as text, wraps, never breaks the strip or the table (Tasks 4, 6).

### Task 1: The shapes in `@lume/core`

**Files:** Modify `packages/core/src/licence/token.ts`, `packages/core/src/licence/state.ts`; create
`packages/core/src/licence/fleet.ts`, `packages/core/src/licence/fleet.test.ts`; export from `licence/index.ts`.

**Produces:**
- `HEALTH_PROBLEMS` (readonly tuple of the 7 keys), `type HealthProblem`.
- `fleetHealthSchema` (zod, strict) and `type FleetHealth = { uptimeS: number; dbBytes: number; diskFreePct: number |
  null; errors24h: number; queue: { waiting: number; retrying: number; failed24h: number }; remindersLate: number;
  restoreTest: { at: string; ok: boolean } | null; problems: HealthProblem[]; sourcesNeedingAttention: number }`;
  `capHealth(h): FleetHealth` (integers, caps: counts ≤ 1e9, pct 0–100, unique known problems).
- `announcementClaimSchema` (strict): `{ id: uuid, title 1–80, body 1–600, kind: "update"|"maintenance", audience:
  "everyone"|"admins", windowStart: iso|null, windowEnd: iso|null, endsAt: iso }`; `type AnnouncementClaim`.
- `licencePayloadSchema` gains `announcements: z.array(announcementClaimSchema).max(3).optional()`.
- `LicenceView` gains `announcements: AnnouncementClaim[]` (from the payload, `[]` when absent; ones whose `endsAt`
  has passed are dropped by `licenceState`).
- `checkBody` takes optional `accepts?: string[]`, `health?: FleetHealth | null`, `seen?: { id: string; people:
  number }[]` and includes each only when given (an older call produces today's body exactly).

**Tests (write first):** checkBody without the new options equals today's object; with them includes exactly the
listed keys; capHealth drops unknown problems and caps; payload with `announcements` verifies, with an unknown key in
a claim does not; `licenceState` drops ended announcements.

### Task 2: Licence server — storage and the check

**Files:** Create `apps/licence/migrations/0006_fleet.sql`; modify `apps/licence/src/server/check.ts`,
`apps/licence/src/lib/sign.ts`; tests in `apps/licence/src/server/check.test.ts`.

- Migration: `check_ins.health jsonb`, `check_ins.accepts text[]`; tables `announcements`, `announcement_clients`,
  `announcement_seen` per spec §2.1 (checks for lengths, kind, audience, window both-or-neither, ends after starts,
  ≤ 60 days).
- `checkSchema` gains optional `accepts` (array ≤ 8 of strings ≤ 32), `health` (core schema), `seen` (≤ 3).
- `record()` stores health and accepts on the check-in row; upserts `announcement_seen` for ids that belong to the
  client.
- `liveAnnouncements(db, clientId, now)` → claims (≤ 3 newest); `issueToken` passes `announcements` only when
  `accepts` includes `"announcements"` (the key is absent otherwise).

**Tests:** body without accepts → payload keys exactly today's; with accepts → announcements live for this client
(all-clients, chosen client, not another's, not withdrawn, not ended, not scheduled); health stored; unknown problem
key → 400; seen counts recorded only for this client's announcements.

### Task 3: Licence server — fleet, announcements API, the bell

**Files:** Create `apps/licence/src/lib/fleet.ts` (+ test), `apps/licence/src/server/fleet.ts` (+ test); modify
`api.ts`, `clients.ts` (`getClient` health + trend), `lib/alerts.ts` (+ test).

**Produces:** `fleetStatus(latest, now)` → `"down"|"look"|"none"|"ok"`; `problemsOf(health)` → `{ key, severity:
"red"|"amber", short, words }[]` (disk under 5% red, under 15% amber, failed jobs, errors ≥ 20, restore test, each
problem key); `GET /api/fleet`; `GET/POST /api/announcements`, `POST /api/announcements/:id/withdraw` with reach;
`getClient` → `health`, `healthTrend` (one point a day, 14 days, latest per day); bell alerts `look:<client>` (amber,
fingerprint = sorted problem keys) and `disk:<client>` (red); events "Announcement: <title>" on publish/withdraw.

**Tests:** status rules (each threshold, both sides); problem words; reach counting (reached, cannot, waiting);
withdraw; validation (lengths, window, 60 days); alerts with fingerprints.

### Task 5: LUME API — health, accepts, announcements per person

**Files:** Create `apps/api/src/licence/health-report.ts` (+ test), `packages/db/migrations/0066_announcements.sql`,
schema `announcementDismissals` in `packages/db/src/schema/identity.ts`; modify `keeper.ts` (options `health`,
`seen`; sends `accepts: ["announcements"]`), `app.ts` (5xx counter hook, providers), `routes.ts` (`announcements` in
`LicenceForPerson`; `POST /api/v1/licence/announcements/:id/got-it`), `enforce.ts` (got-it passes the lock),
`apps/api/test/probes.ts`.

- `healthReport(db, { startedAt, errors24h, statfs, now })` → `FleetHealth | null` from readHealth, never throws.
- Errors: a rolling 24-hour count of 5xx (hour buckets) in memory.
- `LicenceForPerson.announcements`: claims visible to this person (admins: owner or settings.manage), not ended,
  each `{ ...claim, gotIt: boolean }`; `seen` sends per id the count of dismissal rows.

**Tests:** report maps problems to keys (source names never sent); failures → null; check body carries accepts,
health, seen; non-admin never sees admins-only; got-it stored per person and reflected; enforce passes got-it while
read-only.
