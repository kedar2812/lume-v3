# Feedback from a client's LUME — what shipped (2026-10-16)

Spec: `docs/superpowers/specs/2026-10-16-feedback-design.md` · Plan: `docs/superpowers/plans/2026-10-16-feedback.md` ·
Canvas: approved 2026-10-16.

## What a client's team sees

1. **Send feedback** in the profile menu at the foot of the sidebar, in the command palette, and on a phone as the
   last item of the tab bar's **More**. Shown only on an install that holds a product key (not the demo, not
   development, not a LUME before setup); a paused or read-only LUME still shows it.
2. The sheet, over the whole window: a kind (**Something's broken** · **An idea** · **Something's confusing**),
   **What happened?**, and up to five screenshots — paste, drop, **Choose images**, or **Capture this screen** where
   the browser can. Each screenshot has **Blur**: drag boxes over anything private; Done burns them into the
   pixels (blurred, then pixelated) before anything leaves the browser, and Send waits until every screenshot is
   ready, so a picture always goes as it was last blurred.
3. Every screenshot is redrawn in the browser: within 2400 px, WebP (JPEG where the browser can't make WebP), stepped
   down until it is 1.5 MB or less, and with nothing the browser added — Chrome puts a colour profile in every
   picture it makes, and it is taken out, as are EXIF, XMP and comments.
4. One plain line says where it goes: the team that makes LUME, with the person's name, email and role, the page
   and the LUME version. Sent: "Sent — thank you." (no sound). Not sent: everything stays, one line says why, and
   Send reads **Try again**. Closing with something written asks first.
5. Their LUME forwards the report at once under its own key and keeps no copy; its audit log notes only the kind and
   how many screenshots. Ten reports an hour per person.

Installations get the sheet with the next LUME release.

## What the owner sees on license.lumecrm.in

- **Feedback** in the sidebar, with the count of new reports beside it.
- The list: New / Fixing / Fixed / All, a kind filter and a search over the words and the reporter; each row shows the
  kind, the words, the page, how many screenshots, the client, the reporter and their role, the status and when.
- One report: what happened; the screenshots (a full-window viewer with Fit / 100% / Download, arrows and Esc);
  status — Seen (set on opening), Fixing, **Fixed in** a release, Not a bug — each written to the client's history;
  the details (client, reporter, email, page, LUME version, browser, screen, theme, received); a private note that
  saves as you type; **Copy as bug report** (Markdown).
- The client's page: a **Feedback** card with their latest reports and a link to all of them.
- **Releases**: "Fixed N reports" on a version's card (or on Latest, before any installation runs it), linking to
  those reports.
- Screenshots of a report closed for 90 days are deleted; the words and details stay.

  `pg_dump` (`/root/lume-licence/backups/licence-pre-0005-2026-10-16-1134.dump`, and

  other path stays at 64 KB. The site before the edit: `/root/lume-licence/backups/nginx-lume-licence.pre-0005`.
- Checked through nginx: `/healthz` 200 (and publicly); a 2 MB POST to `/v1/feedback` reaches the app (400, not

## Rulings made while building

Each is in the executor's ledger with its cost if wrong; the owner report lists them all. The ones that changed
behaviour: Chrome's colour profile is stripped in the browser and the server's byte check stays strict; Seen is set
when a report is first opened; the ten-an-hour limit counts only reports that reached LUME's team; a long browser
string is cut, not refused; the role sent is the client's own role name (or Owner, or No role); the blur editor's
Undo can take away any box, earlier passes' too; on a phone More always shows when Send feedback is offered; the
licence server turns an address away after 120 tries an hour, refused ones included.

## Deferred (minor)

- Every other licence-server answer (400, 404, 413, 500) reads as "couldn't reach its team", and the client's
  server logs nothing: log the status and code.
- Capture this screen may catch the sheet itself on a slow machine (wait for a video frame after hiding).
- Copy as bug report puts the first line, role and client name in the Markdown title unescaped.
- The list's older dates use the UTC day (a report received 00:00–05:30 IST shows the day before).
- A picture the browser can't read (HEIC in Chrome) is ignored without a word; a removed screenshot's source is
  let go only by garbage collection.
- "Discard this report?" isn't announced or focused; the screenshot viewer has no focus trap.
- The browser doesn't run the server's byte check on its own output, so "choose it again" can't help if a browser
  ever adds a part the server refuses (fall back to JPEG).
- The 90-day screenshot clean-up shares a try with the rates refresh, so a failure there skips it that hour.
- Not this change, found on the way (both show only late in the day): Today's "Your day" dots are 12 px links, and
  two due close together fail axe's target-size check (licence.spec's grace and reminder tests run axe on Today);
  follow-ups.spec's own Today screenshots drift with the hour like the visual ones did.
